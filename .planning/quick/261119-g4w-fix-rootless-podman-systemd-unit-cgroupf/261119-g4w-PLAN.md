# Quick task 261119-g4w: rootless Podman cannot start from the system unit

The `ai_bridge` system unit runs Podman as the `nologin` service user (`User=ai_bridge`). That
user has no systemd user session or D-Bus, so rootless Podman's default systemd cgroup manager
and journald events backend fail and the container does not start.

## Tasks

1. **Template:** in `templates/ai_bridge.service.epp`, run every Podman command (`rm`, `pull`,
   `run`, `stop`) as `/usr/bin/podman --cgroup-manager=cgroupfs --events-backend=file`. Leave
   Docker unchanged.
   - verify: `pdk test unit`
   - done: the Podman unit contains the flags on every Exec line and the Docker unit has none.
2. **Specs:** assert the flags on the Podman `ExecStartPre`, `ExecStart` and `ExecStop` lines,
   and assert the Docker unit does not contain `--cgroup-manager`.
3. **Docs:** add a CHANGELOG Unreleased entry and a `docs/TROUBLESHOOTING.md` row for the
   systemd user session / sd-bus / cgroup error.

## Out of scope

Lingering (`loginctl enable-linger`) and Quadlet per-user units. Both need per-user units and
the service user's UID at run time.
